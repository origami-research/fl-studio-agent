# fl-studio-agent 0.1.8

FL Studio no longer stops answering while `fl.meters` plays a project with many mixer tracks.

## Install

```bash
claude mcp add --scope user fl-studio -- uvx --python 3.12 fl-studio-agent
```

Cursor and VS Code: use the install buttons in the [README](https://github.com/origami-research/fl-studio-agent#quick-start).
Claude Desktop: download `fl-studio-agent.mcpb` below and open it.
Then set up FL Studio once, with FL closed (on Windows, in a terminal opened as administrator on your own account):

```bash
uvx --python 3.12 --from fl-studio-agent fl-mcp-install
```

Then open `FLMCP Agent.flp` in FL Studio before you ask for music; it carries the Bridge.

## Updating from 0.1.7 or earlier: rerun fl-mcp-install

The FL controller script is now 0.2.5.
After updating, close FL and run `fl-mcp-install` again (the command above), then reopen FL.
Until you do, the server reports the installed controller as stale, and `fl.meters` refuses before playing, saying to rerun the installer.

## Fixes

- `fl.meters` froze FL on the 23-channel default project, where every channel has its own mixer track (#317).
  Each meter sweep sent one request per track, 24 every 50 ms, while FL played 23 sampled instruments.
  A sweep is now one controller call for every track, every 0.15 s; FL's meters hold a peak long enough to read it.
- Nothing plays, for `fl.meters` or a render, until FL answers.
  A stop FL misses afterwards is sent again once FL answers; if FL never confirms it, the call says FL may still be playing.
- A controller installed by an older release now gets a clear "rerun fl-mcp-install" error instead of "check the arguments".
- The MCP Registry listing is current again: its description fits the registry's 100 characters (#316), which held the 0.1.7 listing back at 0.1.6.

## Known issues

- On Windows, a program that opens the null device `NUL` itself is still refused inside `run`, for example `> NUL` in a `cmd` command ("Access is denied").
  Use `subprocess.DEVNULL` or `os.devnull` from Python, or redirect to a file in the workspace, instead.
- A render plays in real time, so `stems=` takes one play per stem.
