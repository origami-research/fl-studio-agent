# fl-studio-agent 0.1.9

The model can arrange a song and automate controls live, make its own samples in Python, and draw the kick's pumping on a pad or bass.
The run kernel also starts reliably on a busy machine.

## Install

```bash
claude mcp add --scope user fl-studio -- uvx --python 3.12 fl-studio-agent
```

Cursor and VS Code: use the install buttons in the [README](https://github.com/origami-research/fl-studio-agent#quick-start).
Claude Desktop: download `fl-studio-agent.mcpb` below and open it.
Then set up FL Studio once, with FL closed (on Windows, in a terminal opened as administrator on your own account):

```bash
uvx --python 3.12 --from fl-studio-agent fl-mcp-install
```

Then open `FLMCP Agent.flp` in FL Studio before you ask for music; it carries the Bridge.

## Updating from 0.1.8 or earlier: rerun fl-mcp-install

The FL controller script is now 0.2.8.
After updating, close FL and run `fl-mcp-install` again (the command above), then reopen FL.
Until you do, the server reports the installed controller as stale, and the calls added in this release (arranging and automating) fail with a message to rerun the installer.

## New

- **Arrange the song** (#321).
  `fl.new_pattern(name, copy_of=)` and `fl.rename_pattern` make a pattern per section.
  `fl.place(pattern, bars)` puts it in the song; FL then plays the arranged song, so `fl.render` hears it.
- **Automate controls live** (#321).
  `fl.automate(points, bar=, channel= or mixer_track=, slot=, param=)` moves a channel's volume, pan or instrument parameter, a mixer track's volume or pan, or an effect's parameter over time, through FL's own recording.
  FL records the moves into a new pattern placed at the bar, then plays them back so the engine can check them; each take plays twice in real time.
- **Pumping** (#325).
  A compressor's sidechain cannot be set from code, so the kick's pumping is drawn with `fl.automate`: one call per ducked mixer track, with a dip on every kick.
  The `run` description has the recipe.
  On a test box it dipped a pad 14 dB a beat over 16 bars, deepest within 35 ms of the kick.
- **Samples made in Python** (#322).
  `fl.load_sample(ch, "chop.wav")` also takes audio the code wrote: chops, reversed slices, stretched or re-pitched loops made with numpy or librosa.
- **Mixer effect parameters** (#322).
  `fl.effect(mixer_track, slot).params()` and `.set_param()` work on any mixer effect, with FL's own text for each value ("-35.4dB", "20.0:1").

## Removed

- `Track.set_automation`, which rewrote an automation clip in the saved song and reopened FL, is gone (#323).
  Use `fl.automate`.
- The controller's bridge to Image-Line's private MCPTools module is gone (#323); nothing used it.

## Fixes

- The run kernel no longer misses its start on a busy machine (#324, #325).
  It ran below normal priority, so while FL's web view kept a 2-CPU machine busy it barely ran.
  It now runs at normal priority and starts when the server starts.
  A start may take up to 300 s instead of 60 s.
- `fl.automate` accepts steep moves such as a dip on each kick.
  It also finishes a take that runs from bar 1 to the song's end.
- The controller no longer sends FL a message for every screen refresh; nothing read them.

## Known issues

- FL keeps automation about 0.1 s later than asked for (measured on one machine); the pumping recipe starts each dip that much early.
- On a machine whose CPU is saturated (FL's web view on a 2-CPU cloud machine), FL stopped answering when a second long automation started; the cause inside FL is not known (#320 is a similar freeze).
- The agent project's notes still say the kick ducks Synth Bass; it does not, and the next template build drops the line.
- On Windows, a program that opens the null device `NUL` itself is still refused inside `run`; use `subprocess.DEVNULL` or `os.devnull`.
- A render plays in real time, so `stems=` takes one play per stem.
