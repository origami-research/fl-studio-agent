# fl-studio-agent 0.1.16

Every text the model reads (the `run` description, the docstrings `help()` shows, the guides and the agent project's notes) is rewritten to one written standard, `docs/model-text-standard.md`, and CI checks it.
The `run` description now states this host's real values instead of fixed ones.

## Install

```bash
claude mcp add --scope user fl-studio -- uvx --python 3.12 fl-studio-agent
```

Cursor and VS Code: use the install buttons in the [README](https://github.com/origami-research/fl-studio-agent#quick-start).
Claude Desktop: download `fl-studio-agent.mcpb` below and open it.
Then set up FL Studio once, with FL closed (on Windows, in a terminal opened as administrator on your own account):

```bash
uvx --python 3.12 --from fl-studio-agent fl-mcp-install
```

Then open `FLMCP Agent.flp` in FL Studio before you ask for music; it carries the Bridge.

## Updating from 0.1.15

The FL controller script is unchanged (0.2.10), so there is nothing to rerun.
Your existing `FLMCP Agent.flp` is kept, with its old notes, because it is your work in progress.
To start from the new notes, delete it and rerun `fl-mcp-install`, which creates it again.

## Changes

- **The `run` description states what holds on this host** (#352).
  The run budget comes from `FLMCP_RUN_BUDGET_SECONDS` (it always said 600 s), and it says the workspace is the only place code can write only when the host confines the kernel.
  It no longer calls `run` the only tool, which is false where a host offers other tools beside it, and no longer prices images in one provider's tokens.
  Without an FL session (`--workspace-only`) it no longer mentions renders, and it says the guides' examples do not run there.
- **What is read live is said exactly, and once** (#351, #352).
  Notes, playlist clips, automation clips and the project's notes are read from the song FL opened plus the edits made through `fl`, so a change made in FL's own windows is not seen until FL saves the song; everything else is read from FL live.
  `fl`'s description says this; `fl.playlist`, `Track.notes` and `fl.scene` point to it.
  `fl.place` says `fl` cannot remove a clip, which FL's Playlist window can.
- **The arrangement guide's swing keeps its patterns to whole bars** (#351).
  The swing moved each off-sixteenth later without shortening it, so pattern B became 20 beats long and its clips overlapped; it now shortens each moved note by the same amount, so A and B are 16 beats each.
  The guide states the fact behind it: a pattern lasts as long as its notes, rounded up to whole bars, and its clips play that long.
- **Docstrings state facts only** (#352).
  Engineering references (design documents, source files, dates) are gone; `Note` states its units and `PluginParam` says what it holds.
  `fl.sounds` and `fl.effect` no longer give workflow advice, and the sound-query example names no genre.
- **Guides** (#352).
  Each guide's description says what it covers.
  The mixing guide no longer describes the agent project's routing, EQs and faders, which are not true of your own project.
  Examples name no chord progressions or genres.
- **The agent project's notes** no longer repeat how a sampler pitches its sample; `help(fl.load_sample)` says it (#352).

## Known issues

- `fl.scene()` takes about 4 s, more with many patterns.
- The project's notes follow a channel's name, so a channel FL renames (a loaded sample or preset) loses its line.
- The sound model and index are still unpublished, so `fl.sounds` ranks by name only and `like=` is refused.
- On Intel macOS, and on Python 3.15 and later, onnxruntime has no wheel, so `fl.sounds` matches by name only there even once the model is published.
- FL keeps automation about 0.1 s later than asked for (measured on one machine); the `sidechain` guide starts each dip that much early.
- On Windows, a program that opens the null device `NUL` itself is still refused inside `run`; use `subprocess.DEVNULL` or `os.devnull`.
- A render plays in real time, so `stems=` takes one play per stem.
- The MCP server's description (`...; confined=true`) is meant for the host, but some MCP clients may show it.
