# fl-studio-agent 0.1.15

When FL Studio does not answer (a dialog open, FL busy or frozen), every read now says so instead of showing the saved song as if it were current.
The agent project's notes state facts only, measured on FL: what each channel holds, the keys it plays, and the pitch MIDI 60 sounds.

## Install

```bash
claude mcp add --scope user fl-studio -- uvx --python 3.12 fl-studio-agent
```

Cursor and VS Code: use the install buttons in the [README](https://github.com/origami-research/fl-studio-agent#quick-start).
Claude Desktop: download `fl-studio-agent.mcpb` below and open it.
Then set up FL Studio once, with FL closed (on Windows, in a terminal opened as administrator on your own account):

```bash
uvx --python 3.12 --from fl-studio-agent fl-mcp-install
```

Then open `FLMCP Agent.flp` in FL Studio before you ask for music; it carries the Bridge.

## Updating from 0.1.14: rerun fl-mcp-install

The FL controller script is now 0.2.10.
After updating, close FL and run `fl-mcp-install` again (the command above), then reopen FL.
Until you do, the server reports the installed controller as stale and `fl.mixer` keeps listing FL's last mixer track.
A machine image built for 0.1.14 must likewise run `fl-mcp-install` from 0.1.15 so it carries the 0.2.10 controller.

Your existing `FLMCP Agent.flp` is kept, with its old notes, because it is your work in progress.
To start from the new notes, delete it and rerun `fl-mcp-install`, which creates it again.

## Changes

- **Reads never present the saved song as current** (#349).
  0.1.14's notes said that when FL does not answer, `fl.scene()` "reads the rest from the saved song instead of raising".
  That was wrong to do: a trial FL never saves, so the saved song is always the starting project, and with a dialog open the scene showed an empty song as the current one.
  `fl.scene()`, `fl.channels`, `fl.tempo` and channel names are now FL's answer, or the error "FL Studio did not answer in time", whose fix says FL may be held by an open dialog.
  `SceneSummary.unanswered` is gone; its `patterns`, `mixer` and `tempo` are always present.
  What FL cannot report at all (notes not written this session, the playlist's clips, automation clips, the project's notes) still comes from the song FL opened with this session's edits, and the docstrings say a change made in FL's own windows is not seen.
- **Tempo and channel levels no longer rewrite the saved song** when FL does not answer (#349).
  That path killed and reopened FL, which lost its unsaved work; they now raise like every other control.
- **The agent project's notes state facts only** (#349).
  They no longer name genres, a song structure or a workflow.
  Measured on FL: the 808 and the Bass sound C2 on MIDI 60 (two octaves down), the Sax and Synth 2 sound C5, Synth 1 sounds C3; the Bass plays MIDI 36-96, the Sax 24-72, and the E-Piano, Choir and Guitar 24-96.
- **One silence threshold** (#349).
  A render of the whole mix was refused as silent below -60 LUFS while `Render.silent` meant -70; both now use -70 (BS.1770's gate), so a quiet but audible mix is no longer refused.
- **`fl.mixer` and `fl.scene()` print a mixer track the same way**, in ASCII: `113 'Reverb Send', vol 0.4; effects 0:Fruity Reeverb 2; sends 2:0.8, 3:0.8` (#349).
  FL's last mixer track, which FL names nothing, is no longer listed as in use.
- **`fl.effect(track, slot)`** reads that one slot instead of the whole mixer (#349).
- **`fl.read_wav` of a missing file** answers at once (#349); it took about 15 s on a fresh machine.
- **`theory.drums`** plays MIDI 60 by default, the key a sampler plays its sample at its own pitch (#349); it was MIDI 24.
- **`run`'s description** lists `fl.save` only when FL is licensed (`FLMCP_FL_LICENSE`, licensed by default), since a trial FL cannot save (#349).
  With `--workspace-only` it says that `fl.guide()` and `fl.read_wav()` of a file you wrote work.

## Removed

- **`fl.export_offline`** (#349): a second way to render, licensed FL only. Use `fl.render`.
- **`fl.file_edit`** (#349): every edit applies live, and during a match it always raised.

## Known issues

- `fl.scene()` takes about 4 s, more with many patterns.
- The project's notes follow a channel's name, so a channel FL renames (a loaded sample or preset) loses its line.
- The sound model and index are still unpublished, so `fl.sounds` ranks by name only and `like=` is refused.
- On Intel macOS, and on Python 3.15 and later, onnxruntime has no wheel, so `fl.sounds` matches by name only there even once the model is published.
- FL keeps automation about 0.1 s later than asked for (measured on one machine); the `sidechain` guide starts each dip that much early.
- On Windows, a program that opens the null device `NUL` itself is still refused inside `run`; use `subprocess.DEVNULL` or `os.devnull`.
- A render plays in real time, so `stems=` takes one play per stem.
