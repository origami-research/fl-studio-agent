# fl-studio-agent 0.1.3

Fixes from a live test on Windows: `run` and the Bridge download now work on a user's Windows machine.

## Install

```bash
claude mcp add --scope user fl-studio -- uvx --python 3.12 fl-studio-agent
```

Cursor and VS Code: use the install buttons in the [README](https://github.com/origami-research/fl-studio-agent#quick-start).
Claude Desktop: download `fl-studio-agent.mcpb` below and open it.
Then set up FL Studio once, with FL closed (on Windows, in a terminal opened as administrator on your own account):

```bash
uvx --python 3.12 --from fl-studio-agent fl-mcp-install
```

Then open `FLMCP Agent.flp` in FL Studio before you ask for music; it carries the Bridge.

## Fixes

- `run` works on Windows. Before, every call failed (kernel exit 106, "No pyvenv.cfg file"), because the sandbox could not read the engine's own Python in uv's user folder.
- The Bridge download works on machines that don't have GitHub's root certificate: it now checks HTTPS against the operating system's certificate store.
- When FL Studio has several versions installed, the installer picks the newest by version number.
- An install that ends with warnings no longer prints "Next:" as if it were done.
- `fl-mcp-doctor` says when FL is open but no Bridge is running, and tells you to open `FLMCP Agent.flp`. A failed `render` tells the model to ask you to open the agent song.
- Notes written in FL's step sequencer are now read correctly.
- The project-file library is updated to flpkit 0.9.0.

## Docs

README and SETUP gain the steps the Windows test found missing: open `FLMCP Agent.flp`, start loopMIDI with Windows, never save the agent project in the FL trial, run the installer elevated on your own account, and install loopMIDI without winget on Windows Server.
