# fl-studio-agent 0.1.7

The MCP server now has one tool, `run`.
The model writes Python, and `fl` in that Python does everything the old tools did, and more.

## Install

```bash
claude mcp add --scope user fl-studio -- uvx --python 3.12 fl-studio-agent
```

Cursor and VS Code: use the install buttons in the [README](https://github.com/origami-research/fl-studio-agent#quick-start).
Claude Desktop: download `fl-studio-agent.mcpb` below and open it.
Then set up FL Studio once, with FL closed (on Windows, in a terminal opened as administrator on your own account):

```bash
uvx --python 3.12 --from fl-studio-agent fl-mcp-install
```

Then open `FLMCP Agent.flp` in FL Studio before you ask for music; it carries the Bridge.

## Updating from 0.1.6 or earlier: rerun fl-mcp-install

The FL controller script is now 0.2.4.
After updating, close FL and run `fl-mcp-install` again (the command above), then reopen FL.
Until you do, the server reports the installed controller as stale, and `fl.mixer`, solo and mute renders and filter-group-safe channel addressing need the new controller.

## Breaking change: one tool, `run`

The server serves only `run`.
These tools are gone; here is what replaces each, inside `run`:

| Removed | Use instead |
| --- | --- |
| `get_scene` | `fl.scene()` (the same digest), or `fl.tempo`, `fl.channels`, `fl.mixer`, `fl.playlist`, `fl.patterns` |
| `check` | `fl.meters(bars=2, start_bar=1)` |
| `render` | `fl.render("mix.wav")`, which returns the WAV's `Path` with `.span` |
| `analyze` | `fl.read_wav(path)` and the preinstalled libraries (numpy, librosa, pyloudnorm, ...) |
| `shell`, `read_file`, `write_file`, `edit_file`, `glob`, `grep` (behind `FLMCP_WORKSPACE_TOOLS`) | plain Python in `run`: `open()`, `pathlib`, `subprocess`, `!cmd`; `FLMCP_WORKSPACE_TOOLS` is gone |

Inside `fl`, these names changed:

- `fl.check` is `fl.meters`.
- `fl.analyze` is gone; build the analysis you need from `fl.read_wav` and the libraries below.
- `Track.set_channel_levels` is `Track.set_levels`.
- `fl.add_effect` is gone: `fl.load_preset(ch, effect_preset)` adds the effect live.

`fl-mcp --workspace-only` (for computer-use runs) now serves `run` with no FL session: plain Python works, and `fl` calls are refused.
A client that called the old tools by name must call `run` with code instead.
The `run` description is the whole manual: every `fl` method with a one-line meaning, the library list and two recipes.

## New

- **Reads.**
  `fl.mixer` (the mixer tracks in use, with their effects and sends), `fl.playlist` (the song's clips) and `fl.patterns` (the patterns that hold something, and the selected one).
- **Render options.**
  `fl.render("mix.wav", bars=, start_bar=, solo=[ch], mute=[ch], stems=...)` renders a range of bars, a channel alone or with channels muted.
  `stems="channels"` or `stems="mixer"` records one WAV per channel or mixer track, only for channels with notes in those bars (`.skipped` lists the rest); `stems=["Bass", 3]` records exactly those channels.
  A solo or mute render sets the mutes in one controller call each way and puts them back afterwards; if FL stops answering, the error names every channel that may still be muted.
- **Stock sounds.**
  `fl.sounds("808 kick", kind="sample"|"preset")` searches FL's stock library, and `fl.load_sample` / `fl.load_preset` load a result.
  `fl.stock_folder` is readable from `run`, so `fl.read_wav` opens a stock sample to listen before loading it.
- **Preinstalled libraries.**
  numpy, scipy, soundfile, librosa, matplotlib, pyloudnorm, mido, music21 and Pillow are installed with the server.
  Anything else is `%pip install` inside `run`.
  A matplotlib figure or PIL image that the code displays comes back to the model as an image (at most 4 per call).

## Fixes

- With an FL channel filter group active, channel indices counted only that group's channels, so a write could land on the wrong channel.
  Every channel index is now FL's global index, whatever the rack shows.
- A note write on a licensed FL could report "(0 notes)" for a real write when FL had not saved the file yet.
  The readback now counts only when FL rewrote the project file.
- On Windows, `subprocess.DEVNULL` and `open(os.devnull)` raised `PermissionError` inside `run`; they work now.

## Known issues

- On Windows, a program that opens the null device `NUL` itself is still refused inside `run`, for example `> NUL` in a `cmd` command ("Access is denied").
  Windows does not let the sandbox grant `NUL`, so the kernel substitutes a workspace file for `subprocess.DEVNULL` and `os.devnull`.
  Use those from Python, or redirect to a file in the workspace, instead of `NUL`.
- A render plays in real time, so `stems=` takes one play per stem.
