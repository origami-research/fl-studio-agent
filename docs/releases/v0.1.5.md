# fl-studio-agent 0.1.5

`render` no longer puts the audio in its result, so a conversation keeps working after a render.

## Install

```bash
claude mcp add --scope user fl-studio -- uvx --python 3.12 fl-studio-agent
```

Cursor and VS Code: use the install buttons in the [README](https://github.com/origami-research/fl-studio-agent#quick-start).
Claude Desktop: download `fl-studio-agent.mcpb` below and open it.
Then set up FL Studio once, with FL closed (on Windows, in a terminal opened as administrator on your own account):

```bash
uvx --python 3.12 --from fl-studio-agent fl-mcp-install
```

Then open `FLMCP Agent.flp` in FL Studio before you ask for music; it carries the Bridge.

## Fixes

- `render` returned the whole WAV as base64 text (`wavBase64`) in its result.
  A 23-second render was millions of tokens, so Claude Desktop and Claude Code failed with "prompt is too long" on the next request.
  The result is now `{"path", "bytes", "span", "actions"}`: the WAV's path, its size, and what played (song or pattern, beats, tempo, seconds).
  Open the file at `path` to listen; the model's code in `run` reads it with `fl.read_wav` or `fl.analyze`.

## Breaking change

- The `render` result no longer has `wavBase64` or `note`. A client that collected the audio from `wavBase64` reads the file at `path` instead.

## Known issue

- `analyze` can report the wrong tempo for syncopated beats, for example 113 BPM for an 85 BPM boom-bap pattern.
  The `render` result's `span.tempo_bpm` is FL's own tempo.
