# fl-studio-agent 0.1.4

The model's code is now sandboxed on macOS too, and the Bridge plugin is required.

## Install

```bash
claude mcp add --scope user fl-studio -- uvx --python 3.12 fl-studio-agent
```

Cursor and VS Code: use the install buttons in the [README](https://github.com/origami-research/fl-studio-agent#quick-start).
Claude Desktop: download `fl-studio-agent.mcpb` below and open it.
Then set up FL Studio once, with FL closed (on Windows, in a terminal opened as administrator on your own account):

```bash
uvx --python 3.12 --from fl-studio-agent fl-mcp-install
```

Then open `FLMCP Agent.flp` in FL Studio before you ask for music; it carries the Bridge.

## Security

- On macOS, the Python the model writes in `run`, and the shell and file tools when they are on, now run in a sandbox limited to their own workspace folder, as on Windows.
  Before, on macOS they ran with your full access.
  The sandbox can read and write its folder and reach the public internet (so `pip install` works); it cannot read your home folder or other files, reach services on this computer (FL's control ports included), or touch other programs.
  The engine, FL Studio and the Bridge are not sandboxed, and the model's `fl` calls reach FL through the engine as before.
  The MCP server now reports `confined=true` on macOS.
- On both macOS and Windows, the engine's check before any model code runs now also proves that nothing outside the workspace can be written, that your home folder cannot be listed, and that this computer's own network services cannot be reached; if any check fails, the code does not run.
- On macOS the sandbox does not block other computers on your local network.
  Details: [docs/38](https://github.com/origami-research/fl-studio-agent/blob/main/docs/38-python-kernel.md).

## Changes

- The Bridge plugin is required, not optional.
  With no Bridge running in FL (another song open, or none installed), note writes and `render` are refused with the fix, open `FLMCP Agent.flp`, instead of note writes saving FL's open song and restarting FL for each write.
  `fl-mcp-doctor` reports `"status": "not_ready"` (it was `"degraded"`) whenever any part, the Bridge included, is not connected, and says to rerun `fl-mcp-install` when the Bridge is not installed.
  `fl-mcp-install --no-bridge` stays only for hosts that install their own Bridge build.
- Rerunning `fl-mcp-install` from a terminal that is not elevated no longer warns that it cannot write the Bridge when the installed Bridge is already current.
- The installer's last line now says to open `FLMCP Agent.flp`.
